### WM Register Layout (from webOS code patterns)
- Each WM has 24 bytes (0x18) of registers
- V31_AXI_OUT_OFF + 20 = base of WM0
- WM(n) = V31_AXI_OUT_OFF + 20 + (24 * n)

================================================================================
## Key Observations for VFE31 Driver Development
================================================================================

1. WebOS used OUTPUT_1_AND_3 mode (WM0/WM1 + WM4/WM5) for preview/video
2. WM1 and WM5 were DISABLED in webOS preview mode (only captured Y planes)
3. Register layout matches our current implementation
4. Test generator was never implemented in userspace HALs
5. AXI burst length defaults to 4
6. Each WM has 6 registers (24 bytes): PING, PONG, ADDR_CFG, UB_CFG, IMAGE_SIZE, IRQ_SUBS

================================================================================
## Confirmation of Our Current Implementation
================================================================================

Our driver (camss-vfe-3-1.c) has correct register offsets:
- WR_PING_ADDR  = 0x050 + 0x18 * n
- WR_PONG_ADDR  = 0x054 + 0x18 * n
- WR_UB_CFG     = 0x05C + 0x18 * n
- WR_IMAGE_SIZE = 0x060 + 0x18 * n

This matches V31_AXI_OUT_OFF + 20 (header) + register_offset pattern.
V31_AXI_OUT_OFF appears to be 0x040 (AXI_OUT_MODE register).
So: 0x040 + 0x10 (20 decimal) = 0x050 = WR_PING_ADDR[0] ✓
